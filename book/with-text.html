はじめに · 1/2

社会人の僕が、Cloudflare OS と出会うまで

こんにちは。僕は 30 代の IT 企業に勤める会社員です。日々の業務では、組織の標準アプリを使いつつ、自分の担当だけに残る「ちょっとした不便」にも頭を悩ませていました。

売上管理や勤怠のような大きい仕組みは、会社が用意した公式ツールで足ります。困るのは、その外側です。自分だけが持っている提携先との手順。二人だけで回しているチェック表。部署内の小さな集計。開発チームに「標準アプリにしてほしい」と頼んでも、優先度が上がらない。かといって、自分でアプリを一から作るには工数がかかりすぎる。そんなすき間を、ずっと抱えていました。

そんなとき出会ったのが、Cloudflare OS でした。生成 AI とおしゃべりしながら、個人がちょっと欲しいアプリをその場で作り、そのまま使える「場所」です。大きい業務システムを置き換えるものではなく、人ごとに違う業務の「少しだけ改善したい」に応えてくれる OS だと、触ってみて確信しました。

実際に使い始めると、チャットに頼むだけでスライドや小さな道具が手元に残ります。コードを書かなくても形になり、足りなければ会話で足せます。同僚と一緒に触る共有も、アプリのテンプレートとして配ることもできます。公式の言葉では、それが Gadget（個人用の小さなアプリ）や Blueprint（アプリのテンプレート）と呼ばれている部分です。

はじめに · 2/2

はじめに

もう一つ、僕が大きく感じたのは、社内の閉域で使える点です。自社のアカウントに載せ、入り口を絞り、外のサービスへの接続は Gatekeepers 経由にできます。鍵を AI に丸ごと渡さず、必要なリソースだけ通す。便利さと安全を、同じ土台の上で考えられます。

Cloudflare 社内では、エンジニア以外も含め多くの人が日々これを使っているそうです。オープンソースとして公開された狙いは、そのまま Cloudflare のブランドを借りるだけでなく、自社の用語や手順を載せた「Your Company OS」を持てるようにすることにあります。

この本では、僕が Cloudflare OS をどう捉え、どう触ってきたかを、画面操作中心に解説していきます。プログラミングの深い知識は前提にしません。ボタンとチャットの流れが追えれば十分です。第1章で全体像と用語、第2章で起動、第3章で画面、第4章で機能、第5章から実践を四つ通します。急ぎなら第2章のあと第5章へ進み、用語で詰まったら第1章と第4章へ戻ってください。

生成 AI に頼むだけで一瞬アプリができ、一緒に使える環境までそろう。そんな働き方の一端を、この本で体験してもらえたら嬉しいです。皆さんの「ちょっと欲しい」が、標準開発の待ち行列に並ばずに済む一助になれば幸いです。

環境の説明

Cloudflare OS の使い方（置き方）は、大きく分けて三種類あります。

  • 自分のパソコンに入れて動かす（ローカル）
  • ブラウザから、自分の Cloudflare アカウントへ載せる
  • 社内向けに整え、社内サーバーなどで本番運用する

この書籍では、そのうちローカルのパソコンにインストールし、その中で検証していく進め方をとります。手元で起動し、画面を開き、第5章以降の実践まで同じ環境で試せます。手順は次の節から具体的に書きます。

画面の説明やキャプチャは、主に macOS を例にします。Windows でのインストールや起動の手順も基本は同じです。メニュー名やターミナルの開き方が少し違う程度で、このあとのコマンドやブラウザでの確認はそのまま使えます。

社内で本格的に運用する場合は、社内のサーバーや会社の Cloudflare アカウント上で動かすことになります。設定やセキュリティの方針は組織ごとに異なります。その手順や設計は本書の範囲には含めません。まずは手元で動かして全体像を掴むことが、この章のゴールです。

注意

Cloudflare OS は Early Access です。画面や手順は更新で変わることがあります。つまずいたら公式の README もあわせて確認してください。

ローカルにインストールをしよう！

ここからは、パソコンに Cloudflare OS を入れて動かします。公式も「pnpm を入れて起動」が基本です（https://github.com/cloudflare/cloudflare-os ）。

画面のボタン名やデザインは将来変わることがあります。覚えるのは「何を入れるか」です。入れるものは次の4つです。

順番 入れるもの ひと言

第2章 · 3 macOS の手順

第2章 環境を用意する
3

macOS の手順

0. まず「ターミナル」を開く

このあとの文字（コマンド）は、ブラウザの検索窓ではなく、ターミナルというアプリに打ちます。文字を入力できる専用の窓です。

開き方の例です。

  • キーボードの Command（⌘）＋ スペース を押し、「ターミナル」と入力して Enter
  • または「アプリケーション」→「ユーティリティ」→「ターミナル」

開いたら、この本のコード枠の文字をコピーして貼り付け、Enter キーを押します。1行ずつが安心です。

1. Node.js を入れる

Safari などで https://nodejs.org/ を開きます。いちばん目立つダウンロード（「Get Node.js」など）から入れます。出てきたインストーラ（.pkg など）をダブルクリックして完了まで進めます。ボタン名は変わることがありますが、「ダウンロード → インストール完了」ができれば大丈夫です。

入れ終わったら、いったんターミナルを閉じて、もう一度開き、次を入力して Enter します。

node -v
npm -v

それぞれ番号（例: v24.x.x）が出れば成功です。

2. Git を入れる

ターミナルに次を入力して Enter します。初めての Mac では、途中で開発ツールのインストール確認が出ることがあります。「インストール」を選んでください。

xcode-select --install
git --version

git version … のように番号が出れば OK です。うまくいかないときは https://git-scm.com/ の macOS 案内も見てください。

3. pnpm を入れる

同じターミナルで、次を実行します。1行ずつコピーして Enter で大丈夫です。

第2章 · 3 macOS · 起動

第2章 · macOS の手順

4. Cloudflare OS を取って起動する

まだターミナルを開いたままにしておきます。次の行を、上から順にコピーして Enter します（1行ずつが安心です）。

cd ~
git clone https://github.com/cloudflare/cloudflare-os.git
cd cloudflare-os
pnpm install
pnpm run-local

意味はざっくり、「自分のフォルダへ移動 → 公式のプログラムをダウンロード → 中に入る → 必要な部品を入れる → 起動」です。初回は数分かかることがあります。止めるときは、ターミナルで Control + C を押します。

5. ブラウザで開く

ターミナルはそのままにしておき、Safari や Chrome を開きます。いちばん上のアドレス欄（URL を入れる場所）に次を入力して Enter します。

http://localhost:8787

Cloudflare OS の画面が出れば、Mac での準備は完了です。

第4章 · 3 Gadget と Blueprint

第4章 動かして機能を知る
3

Gadget と Blueprint

さきほどの節で、「今日やること」のミニアプリを作りました。こうして作られたアプリのことを、Gadget と呼びます。自分専用の小さな道具で、直しても他人のコピーには影響しません。

一方 Blueprint は、そのアプリの型（アプリのテンプレート）です。自分が作ったものを「人にも同じような道具を持って使ってほしい」ときに使います。渡すのは中身のデータではなくコードのスナップショットなので、相手は自分用の Gadget を新しく起こして使います。あなたの Gadget を一緒に開くわけではありません。

図: Gadget（自分の道具）と Blueprint（アプリのテンプレート）

データやパスワードは Blueprint には付きません。作り方と画面での見方を、このあとに整理します。

Blueprint の作り方・見方

作る — 画面の案内どおり、ワークスペースを Blueprint として公開する（Publish a workspace as a blueprint）か、Explore から取り込む／Upload .gadget でファイルを上げる、といった手順になります。バージョンでボタン名は変わることがあります。

第4章 · 4 共有の二通り

第4章 動かして機能を知る
4

共有の二通り

ほかの人と使うときは、ざっくり二通りです。第1章の図と同じ考え方です。

  • 一緒に使う — 同じ Gadget を共同で触る（中身を共有）
  • アプリのテンプレートを渡す — Blueprint として配り、相手は自分用コピーを作る（データは付かない）

図: コピー（テンプレート）と共有（一緒に使う）— 第1章と同じ図

メモの中身を一緒に直したいなら共有。型だけ渡して各自で使わせたいなら Blueprint。迷ったら、まず個人用の Gadget のまま動かし、必要になってから決めて構いません。

第4章 · 5 Gatekeepers

第4章 動かして機能を知る
5

Gatekeepers と安全の考え方

Gatekeepers は、外のサービス（GitHub など）への出入りを見張る仕組みです。最初、エージェントも Gadget も外にはつながっていません。つなぐときは、使いたいリソースだけを選び、鍵は Gatekeepers が持ち、エージェントは直接持ちません。

図: 外へは Gatekeepers 経由 — 第1章と同じ図

さきほどのメモは、外のサービスなしでも動きます。GitHub や Slack をつなぐ操作は第7章です。第3章のセットアップで Connect your services をスキップしたのも、この順序のためです。

注意

外へ書き込む設定をするときは、権限の範囲を狭くしてください。読んだデータが、見てはいけない人に漏れないよう、組織のルールも確認します。

第7章 · 4 GitHub OAuth

第7章 実践③ 外部サービスとつなぐ
4

GitHub OAuth

Connect GitHub の画面に、Client ID や Secret の入力欄はありません。ローカルでは、先に GitHub で OAuth App を作り、その値を自分の PC 側に書きます。無いと「GitHub Gatekeeper Not Configured」で止まります。/admin の操作ではありません。

GitHub の Settings → Developer settings → OAuth Apps（GitHub Apps ではない）→ New OAuth App を開き、次を入れます（ローカル localhost:8787 の例）。

項目 入れる内容（ローカル例）
Application name 任意（例: Cloudflare OS Local）
Homepage URL http://localhost:8787
Application description 任意。空欄のままでよい
Authorization callback URL http://localhost:8787/gatekeeper/github/oauth
（末尾スラッシュなし。ここだけ正確に）
Enable Device Flow オフ（チェックしない）

Register application のあと Generate a new client secret を押し、Client ID と Client secret を控えます。次のページで、この値をローカルの Cloudflare OS に書き込みます。

注意

OAuth App と GitHub App は別物です。ここは OAuth App を使います。サーバーを公開 URL で動かしているときは、callback URL もその URL に合わせます。

第7章 · 5 ローカル側の設定

第7章 実践③ 外部サービスとつなぐ
5

ローカル側の設定

GitHub で控えた ID と Secret は、Connect 画面には貼りません。第2章で clone した cloudflare-os フォルダを開きます（Windows の起動手順は P.20、Mac は P.17 付近。ホーム直下の cloudflare-os であることが多いです）。

その中の packages/gatekeeper-github フォルダに、.env という名前のファイルを作り、次の2行を書きます。書いたらターミナルで pnpm run-local を一度止めてから起動し直してください。

.env に書く内容

CLIENT_ID=（控えた Client ID）
CLIENT_SECRET=（控えた Client secret）

ファイル名は先頭にドットの付いた .env です（env.txt ではありません）。

保存して再起動すると、Gatekeepers の Continue to GitHub から GitHub の許可画面に進めます。

大切に扱う

Client ID と Client secret は、GitHub への合鍵に近い大事な情報です。メモやパスワード管理アプリに控え、他人に渡さないでください。.env も GitHub など公開の場所に載せないでください。載ると、第三者があなたの代わりに接続できてしまいます。

まだ Not Configured と出るときは、次を順に確認します。(1) ファイルが packages/gatekeeper-github/.env にあるか (2) 行名が CLIENT_ID / CLIENT_SECRET か (3) 保存のあと pnpm run-local を止めて起動し直したか。

おわりに

おわりに

この本では、Cloudflare OS を開き、エージェントに頼み、スライドや小さなアプリを残し、GitHub などを Gatekeepers 経由でつなぐところまで手を動かしました。完璧な一文を一発で書くより、作って・見て・直す繰り返しの方が、現場では役に立ちます。画面は Early Access で変わりますが、この順番は残ります。

押さえておきたいのは、Cloudflare OS が向かう先です。全社の基幹を置き換えるような大きなアプリを作る場所ではありません。社内の SE がなかなか手が回らない一方で、現場の人は毎日困っている。そんな小さなアプリを、一般の従業員が自然言語で作れるようにする。メモ、看板、Issue の一覧。第5章から第7章で触れたものは、その一例です。

エージェントと小さなアプリを仕事に載せていくと、人それぞれの業務の進め方が少しずつ変わります。組織の中では「作ったものをどう公開し、どう配るか」がいつも難題ですが、共有や Blueprint など、Cloudflare OS にはそのための仕組みがあります。個人の工夫が、チームの道具に育ちやすい土台です。

まずは小さく始めてください。一本書いて Accept し、明日また直す。使ってみて初めて、自分にとっての価値が見えてきます。

最後まで読んでくださり、ありがとうございました。あなたの次の一歩に期待しています。
