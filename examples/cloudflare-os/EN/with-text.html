Preface · 1/2

How I found Cloudflare OS at work

Hi. I’m Masahiro Nakagawa, an office worker in my thirties at an IT company. Day to day I use the company’s standard apps, but I still bump into small annoyances that only show up in my own work.

For big systems - sales tracking, time sheets - the official tools are fine. The real friction lives outside them. Steps only I share with a partner. A checklist two of us keep alive. A tiny tally inside the team. Asking engineering to turn that into a standard app rarely moves the queue. Building an app myself from scratch costs too much time. I lived with those gaps for a long time.

Then I found Cloudflare OS. It’s a place where you chat with generative AI, build the small apps you want, and use them right away. It doesn’t replace large business systems. After using it, I became convinced it answers the “I just want this one thing a little better” requests that differ from person to person.

Once I started, asking in chat left slides and small tools on my desk. They take shape without me writing code, and if something is missing I can add it in conversation. I can share them with a colleague or hand them out as app templates. In product language, those are Gadgets (small personal apps) and Blueprints (app templates).

Preface · 2/2

Preface

Another thing that stood out: it can run inside a closed company setup. Host it on your organization’s account, tighten who can enter, and route outside connections through Gatekeepers. You don’t hand every secret to the AI; only the resources you choose pass through. Convenience and safety share the same foundation.

Inside Cloudflare, many people - including non-engineers - use this every day. Open-sourcing it isn’t only about borrowing the Cloudflare name. The real point is that you can host a “Your Company OS” with your own words and workflows.

In this book I explain how I see Cloudflare OS and how I use it, mostly through on-screen steps. You don’t need deep programming knowledge. If you can follow buttons and chat, you’re set. Chapter 1 covers the big picture and terms, Chapter 2 startup, Chapter 3 the screens, Chapter 4 features, then three hands-on chapters from Chapter 5. If you’re in a hurry, jump to Chapter 5 after Chapter 2 and return to Chapters 1 and 4 when a term trips you up.

Ask generative AI once, get an app, and keep a place where you can use it together. I hope this book helps you try that way of working - and that the “I just need this” ideas on your desk don’t have to wait in the engineering queue. This is an unofficial learning guide by Masahiro Nakagawa of smilior.com.

*Based on information as of August 2026. Cloudflare OS is in Early Access; screens may change. This book is a learning guide, not a replacement for official documentation.

In one sentence

If I had to put Cloudflare OS in one sentence: it’s a place where you chat with generative AI, make the small apps and docs you want, and use them right away. It isn’t an OS you install on a PC like Windows or macOS. You open it in a browser, ask in chat, and the slides or small apps you make stay there, ready to reopen.

How you can run it

There are roughly three ways to run Cloudflare OS.

  • Install and run it on your own computer (local)
  • Deploy from the browser onto your Cloudflare account
  • Harden it for company use and run it in production on internal servers

This book takes the path of installing on a local PC and trying things there. You start it on your desk, open the screens, and use the same environment through the hands-on chapters from Chapter 5. Concrete steps start in the next section.

Screens and captures mostly use macOS as the example. Install and startup on Windows are basically the same. Menu names and how you open the terminal differ a little; the commands and browser checks later work as written.

For production inside a company, you’d run it on internal servers or a company Cloudflare account. Settings and security policy vary by organization. Those designs are out of scope here. This chapter’s goal is to run it locally and get the full picture.

Note

Cloudflare OS is in Early Access. Screens and steps can change with updates. If you get stuck, check the official README too.

Ch. 2 · 2 Install it locally

Install it locally

From here we install Cloudflare OS on your computer and run it. The official basic path is “install pnpm and start” (https://github.com/cloudflare/cloudflare-os).

Button names and design may change later. What matters is what you install. You need these four things.

Step What to install In short
1 Node.js Foundation. Official: https://nodejs.org/
2 Git Fetch the source. Official: https://git-scm.com/
3 pnpm Used to start. Official: https://pnpm.io/
4 Cloudflare OS itself Clone from GitHub and run

The “commands” below go in a dedicated app - not a browser search bar. On Mac that’s Terminal; on Windows it’s PowerShell. How to open each is at the start of that OS’s steps. Read only your OS’s pages.

Ch. 2 · 3 macOS steps

Ch. 2 Set up your environment
3

macOS steps

0. Open Terminal first

The text (commands) below go into an app called Terminal, not a browser search bar. It is a window made for typing.

Ways to open it:

  • Press Command (⌘) + Space, type “Terminal,” and press Enter
  • Or Applications → Utilities → Terminal

Once open, copy text from this book’s code boxes, paste it, and press Enter. One line at a time is safer.

1. Install Node.js

Open https://nodejs.org/ in Safari or another browser. Use the main download (“Get Node.js” or similar). Double-click the installer (.pkg and so on) and finish the steps. Button names change; if you get from download to “install finished,” you are good.

When done, close Terminal and open it again, then type the following and press Enter.

node -v
npm -v

If each prints a version number (for example v24.x.x), it worked.

2. Install Git

In Terminal type the following and press Enter. On a new Mac you may see a prompt to install developer tools - choose Install.

xcode-select --install
git --version

If you see something like git version …, you are fine. If not, also check the macOS guide at https://git-scm.com/.

15

Ch. 2 · 3 macOS · pnpm

Ch. 2 · macOS steps

3. Install pnpm

In the same Terminal, run the following. Copy one line at a time and press Enter.

npm install -g pnpm
pnpm -v

A version number means success. If nothing appears, close Terminal, reopen it, and try again.

16

Ch. 2 · 3 macOS · start

Ch. 2 · macOS steps

4. Get Cloudflare OS and start it

Keep Terminal open. Copy the lines below from top to bottom and press Enter after each (one at a time is safer).

cd ~
git clone https://github.com/cloudflare/cloudflare-os.git
cd cloudflare-os
pnpm install
pnpm run-local

In plain terms: go to your home folder → download the official project → enter that folder → install the parts it needs → start. The first run can take a few minutes. To stop, press Control + C in Terminal.

5. Open it in a browser

Leave Terminal running and open Safari or Chrome. In the address bar at the top, type the following and press Enter.

http://localhost:8787

If the Cloudflare OS screen appears, Mac setup is done.

Gadget and Blueprint

In the previous section you built a “today’s tasks” mini-app. That kind of app is a Gadget - your personal small tool. Your edits don’t affect someone else’s copy.

A Blueprint is the app’s shape (template). Use it when you want others to have a similar tool. You hand over a snapshot of the code, not the data, so each person creates a new Gadget for themselves. They are not opening your Gadget together with you.

Figure: Gadget (your tool) vs Blueprint (app template)

Data and passwords do not attach to a Blueprint. How to make and find Gadgets and Blueprints comes next.

Two ways to share

There are roughly two ways to use something with others - the same idea as the Chapter 1 figure.

  • Work together - touch the same Gadget (share the contents)
  • Hand over an app template - distribute it as a Blueprint; each person makes their own copy (no data)

Figure: Copy (template) vs share (work together) - same as Chapter 1

Want to edit the memo contents together? Share. Want only the shape, used separately? Use a Blueprint. When unsure, keep it as a personal Gadget and decide later.

Gatekeepers and a safety mindset

Gatekeepers sits between you and outside services (GitHub and more). At first neither the agent nor Gadgets are linked outside. When you connect, you pick only the resources you need. Keys stay with Gatekeepers; the agent does not hold them directly.

Figure: Outside only through Gatekeepers - same as Chapter 1

The memo above works with no outside service. Connecting GitHub or Slack is covered in Chapter 7. That is why it was fine to skip Connect your services during setup in Chapter 3.

Note

When you allow writes to outside services, keep permissions narrow. Check your organization’s rules so sensitive data does not leak to the wrong people.

Ch. 7 · 4 GitHub OAuth

Ch. 7 Hands-on 3: Connect external services
4

GitHub OAuth

The Connect GitHub screen has no Client ID or Secret fields. Locally you first create an OAuth App on GitHub and save those values in a file on your PC. Without them you stop at “GitHub Gatekeeper Not Configured.” This is not an /admin step. On a prepared environment, skip this section and the next local config section.

On GitHub: Settings → Developer settings → OAuth Apps (not GitHub Apps) → New OAuth App. Enter the following (local localhost:8787 example).

Field What to enter (local example)
Application name Anything (e.g. Cloudflare OS Local)
Homepage URL http://localhost:8787
Application description Optional; blank is fine
Authorization callback URL http://localhost:8787/gatekeeper/github/oauth
(no trailing slash; this field must match exactly)
Enable Device Flow Off (do not check)

After Register application, press Generate a new client secret and note Client ID and Client secret. On the next page you write them into local Cloudflare OS.

Note

OAuth App and GitHub App are different. Use OAuth App here. If the server runs on a public URL, set the callback URL to match that URL.

Ch. 7 · 5 Local config

Ch. 7 Hands-on 3: Connect external services
5

Local config

Do not paste the ID and Secret from GitHub into the Connect screen. Open the cloudflare-os folder you cloned in Chapter 2 (Windows start steps near p. 20, Mac near p. 17; often cloudflare-os under your home folder).

Inside packages/gatekeeper-github, create a file named .env with the two lines below. Then stop pnpm run-local in the terminal and start it again.

What to put in .env

CLIENT_ID=(your Client ID)
CLIENT_SECRET=(your Client secret)

The filename is .env with a leading dot (not env.txt).

After you save and restart, Continue to GitHub in Gatekeepers can open GitHub’s permission screen.

Handle with care

Client ID and Client secret are like keys to GitHub. Store them in notes or a password manager; do not share them. Do not put .env on a public GitHub repo or similar. If it leaks, someone else can connect as you.

If you still see Not Configured, check in order: (1) file is at packages/gatekeeper-github/.env (2) line names are CLIENT_ID / CLIENT_SECRET (3) after save you stopped and restarted pnpm run-local.

Closing

Closing

In this book you opened Cloudflare OS, asked the agent, kept slides and small apps, and linked GitHub and more through Gatekeepers. In real work, the make → look → fix loop beats writing one perfect sentence. Screens will change in Early Access; this order stays useful.

Keep in mind where Cloudflare OS is headed. It isn’t a place to rebuild the company’s core systems. In-house engineering teams can’t always keep up, while people doing the day-to-day work still struggle. This is about letting ordinary employees build those small apps in natural language. Memos, boards, Issue lists - what you touched in Chapters 5–7 are examples.

As agents and small apps land in daily work, how each person runs their job shifts a little. Inside organizations, “how do we publish and distribute what we made?” is always hard. Sharing and Blueprints give Cloudflare OS mechanisms for that. A personal trick can grow into a team tool more easily.

Start small. Write one request, Accept, and fix it again tomorrow. You feel the value after you use it.
