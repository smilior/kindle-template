# 画面キャプチャ（UI スクショ）

製品・Web UI を書籍に差し込むときの共通ルール。リポジトリ固有のキー名は `AGENTS.md` を優先する。

## 原則

1. **Light モード**で撮る（ダークは文字が潰れやすく、紙面の地色とも合わない）  
2. **フォーカス切り出し**する（フルブラウザ全面は B5 図枠で文字が小さくなる）  
3. **2x 以上**の PNG を `images/` に置く  
4. 差し込み前に **PNG を目視**する（端切れ・暗いまま・文字不可読を落とす）

## 切り出しの目安

| 画面の種類 | 切り出し |
| --- | --- |
| サインイン・登録フォーム | ロゴ〜入力欄〜主ボタン〜補助リンクまで。外周の大きな余白は落とす |
| ウィザード／モーダル | 見出し＋カード＋主ボタン。カルーセルの **画面外スライド**を掴まない |
| アプリシェル（ナビあり） | 左ナビ＋主領域。下の巨大な空きは高さでクリップ |
| 1要素だけ説明したい | ナビだけ／入力欄だけなど **1画面を2図に分割**してよい |

## 撮影手順（Playwright 想定）

```text
1. viewport 例: 1280×800、deviceScaleFactor: 2
2. colorScheme: 'light'
3. アプリがテーマを持つ場合は localStorage / data-mode 等で light を強制
4. 対象領域の getBoundingClientRect で clip を計算（viewport 内に clamp）
5. page.screenshot({ path, clip, type: 'png', animations: 'disabled' })
6. 画像を開いて目視
```

カルーセル型 UI は、オフスクリーンの兄弟パネルを clip しない。`x` が viewport 内のパネルだけを選ぶ。

## HTML への差し込み

```html
<div class="figure-block">
  <div class="figure-box figure-box-wide figure-box-img figure-box-entry">
    <img src="images/ch3-signin.png" alt="…" />
  </div>
  <p class="caption">図: …</p>
</div>
```

- 入口・フォーム系で本文と同居するときは `.figure-box-entry`（高さ上限あり）を使う  
- 文字がまだ小さいときは: 切り出しを狭める → 図を分ける → 枠高を検討、の順

## 本文との整合

- スクショのラベル・遷移と本文の手順を一致させる  
- 製品の初回フローが変わったら、**図と本文を同じターンで**直す  
- キャプションは `図: …`。図内に大きなタイトルを重ねてキャプションと二重にしない  

## やらないこと

- ダークモードのまま紙面に載せる（明示指定がない限り）  
- 余白だらけのフル画面をそのまま縮小して載せる  
- クリップが viewport 外で失敗したのに気づかず古い図を残す  
- パスワードや API キーが平文で写り込んだ図を載せる（マスク入力でも再確認）
