# Kindle Book（対話型レイアウト書籍制作）

B5（182×257mm）向け HTML レイアウトを土台に、**ユーザーと対話しながら**1冊分の原稿・ページを組み立てる。
テンプレートの見た目とクラス構造を崩さず、文言・構成だけを書籍ごとに差し替える。

## 制作スタイル（これが本体）

次の順序を崩さない。本文の長文を先に書かない。

1. **章題を一緒に考える** — タイトルと章立て（目次）を対話で固める  
2. **合意した項目を一気に作成** — 表紙・目次・各章のページ骨格を HTML に一括で起こす  
3. **内容を詰める** — 骨格の上で、章ごと・見出しごとに本文・手順・図・囲みを磨く  

理由: 章題が揺れているうちに本文を書くと手戻りが大きい。先に「何の本か／何章あるか」を固定し、箱を全部立ててから中身を入れると、対話しやすい。

## タスク表（必須）

作業ディレクトリに `book/TASKS.md`（またはリポジトリで定めたタスク表）がある場合、それを **進捗の正本** とする。無ければ骨格作成時に章立てから起こす。

### 毎回やること

1. 作業開始前にタスク表を読む（完了 ✅ / 作成中 🚧 / 未着手 🔲）  
2. 作業対象がタスク表上の妥当な位置か確認する  
3. 作業後に状態とメモを更新する  

### 先行作業への指摘

タスク表が完了していないのに **先の章・先の工程の本格追加** をしようとしたら、実行前に指摘する。

- 未完了の前提をタスク表から列挙する  
- 推奨する次の一手を示す  
- ユーザーが明示的に「飛ばしてよい」と言った場合のみ先行を許可し、タスク表にメモする  

章の肉付けは「ユーザー指定の章から」でよい（前の章がすべて ✅ である必要はない）。ただし次は止めて指摘する: タスク表に無い章を作る、章立て未確定のまま本文を増やす、章題変更後に TASKS／目次／章扉が食い違ったまま進める。

### 章題変更時の生合成

章題・書名・章の増減・順序が変わったら、**同じターンで** 次を揃える。

| 更新先 | 内容 |
| --- | --- |
| タスク表 (`TASKS.md`) | 章名・並び・サマリ |
| `with-text.html` | 表紙・目次・章扉・柱・次章導線 |
| セッション todo（使う場合） | 章題ラベル |

HTML だけ直してタスク表を古い章題のまま残さない。

## いつ読むか

| 状況 | 読むもの |
| --- | --- |
| 起動時・進め方 | この `SKILL.md` |
| 空枠→文字入りのクラス対応 | `references/page-types.md` |
| 画面キャプチャ（UI スクショ） | `references/screenshots.md` |
| マークアップ見本・CSS | `assets/with-text.html`, `assets/with-text.css`, `assets/templates.css` |
| 空枠の骨組み | `assets/index.html` |

作業中は **`assets/` を直接上書きしない**。作業コピーをプロジェクト側に置き、そこを編集する。

## 成果物の置き場所

コピー先リポジトリ（またはカレントの書籍プロジェクト）のルート、もしくは `book/` に次を置く:

```
book/   # またはリポジトリルート
├── TASKS.md        # 進捗の正本（ある場合は必須確認）
├── index.html      # 空枠（任意・参照用）
├── with-text.html  # 実際の書籍（文字入り・主成果物）
├── templates.css
└── with-text.css
```

初回はスキル同梱の `assets/` から **コピー** して開始する。

```bash
# 例: プロジェクト直下に book/ を作る場合（スキル相対パスは環境に合わせて調整）
mkdir -p book
cp .claude/skills/kindle-book/assets/* book/
```

以降の編集対象は **`with-text.html`（＋必要なら CSS）**。空枠の `index.html` は型の確認用に残してよい。

## 対話の進め方

### フェーズ 0 — 起動確認

1. 作業ディレクトリに `with-text.html` があるか確認する。無ければ `assets/` からコピーする。
2. いまどこから再開するかを聞く（章題決め / 骨格の一括作成 / ある章の肉付け / 仕上げ）。

### フェーズ 1 — 企画の最低限

章題に入る前に、次だけ揃える（長時間のヒアリングはしない）。未定なら2〜3案を出して選んでもらう。

- 仮タイトル（サブタイトル・タグラインは任意）
- 想定読者（誰の・どんな悩みか）— 1行でよい
- 読後にできるようになってほしいこと — 1文
- おおよその章数・厚さ（短い / 標準 / 厚め）

### フェーズ 2 — 章題を一緒に作る（合意ゲート）

**ここが最初の本丸。** HTML の一括生成はこのフェーズの OK が出るまで行わない。

1. 章立て案を提示する（はじめに / 各章タイトル / おわりに。節タイトルがあればそれも）。
2. ユーザーと直し合う（統合・分割・言い換え・順番）。必要なら対案を並べる。
3. 合意した一覧を **確定目次** として短く書き戻す（番号付きリスト）。

確定目次に含めるもの:

- 書名（確定 or 仮）
- はじめに（入れるかどうか）
- 各章: 章番号・章題・（任意）1行の章の約束
- おわりに（入れるかどうか）
- 必要なら付録

この段階では本文は書かない。章題の言葉選びと並びだけに集中する。

### フェーズ 3 — 項目を一気に作成（骨格の一括起こし）

確定目次に合意したら、**その項目ぶんをまとめて** `with-text.html` に起こす。見本の Cloudflare 文言は残さない。

一括作成に含めるもの:

| 項目 | やること |
| --- | --- |
| 表紙 | 書名・サブ・タグ・年など |
| 目次 | 確定目次を `toc-list-text` に反映（ページ番号は仮で可） |
| はじめに | 見出し＋プレースホルダ or 短い導入文（1〜2段落） |
| 各章 | 章扉（章番号・章題）＋本文ページの枠（見出しと「ここに書く」レベルの短い仮文でよい） |
| 章末まとめ | 各章に枠があれば空の箇条書き or 仮の3点 |
| おわりに・奥付 | 書名に合わせた枠 |

骨格段階のルール:

- **文字入りクラス**を使う（`references/page-types.md` / `assets/with-text.html` が正）。`.bar` を完成形に残さない。
- 本文は「完成原稿」でなくてよい。章題とページの箱が揃い、あとから差し替えやすい仮文・短い導入で十分。
- 手順・図・囲み・表が章に必要と分かっているなら、空の型ページもこの一括で並べてよい。
- 画像は `figure-placeholder` で差し込み指示を残す。
- ページ番号（`.folio-num`）は仮でよい。通しは仕上げで振る。
- 一括作成のあと、何を置いたかを一覧でユーザーに報告し、次はどの章から肉付けするかを聞く。

典型の並び:

`表紙 → 目次 → はじめに → （章扉 → 本文… → 章末まとめ）× N → おわりに → 奥付`

### フェーズ 4 — 内容を詰める

骨格が立ったあとで、対話により中身を厚くする。

1. ユーザーが指定した章（なければ第1章）から進める。
2. 1ターンでは **1章、またはその中の数見出し** に絞って本文・手順・囲み・表を書き込む。
3. 反映したら変更要約を出し、次の箇所を確認する。
4. 章を跨いで一気に全文を埋めない（ユーザーが明示したときだけ例外）。

詰めるときの優先度の目安: はじめに → 各章本文 → 手順/図/囲み → 章末まとめ → おわりに → 表紙・目次・奥付の最終同期。

### フェーズ 5 — 仕上げ

- 表紙・目次・奥付の文言を最終同期する
- 目次のページ番号を本文と一致させる
- ブラウザで `with-text.html` を開き、印刷プレビューを勧める
- PDF 化: ブラウザの印刷 → PDF。**背景のグラフィック**をオンにする

## レイアウトを崩さないための約束

- **B5・余白・色**は `templates.css` の変数と既存クラスに任せる。独創的なインライン装飾でデザインを作り直さない。
- 見出し: ページ大見出しは `h2.page-title` ＋黄線（`.mark-line-heading`）。節見出しは `h3.sec-title`（本文では `.section-head-text`）。
- 本文は `.body-prose > p`。リストは `.text-list` / 手順は `.steps-list-text`。
- **本文段落は1文字字下げ**（`.body-prose p { text-indent: 1em; }`）。日本語書籍の体裁として必須。囲み・手順注・表・キャプション・箇条書きには付けない。`with-text.css` の定義を消さない／上書きで無効にしない。
- **`h3.sec-title` は1ページに1つまで。** 同じ `sheet-wrap` に節見出しを2つ以上置かない。次の節は必ず別ページ（ページ送り）。`h2.page-title` と `h3` の併用は可。
- **章末まとめ**の `h2` は **「この章のまとめ」**（「この章でできたこと」は使わない）。箇条書きはチェックリスト（`.page-summary .text-list` → ☑、CSS は `with-text.css`）。本文の通常リストは ・ のまま。
- **キーワード早見・用語表**は章の途中ではなく **章の後半〜末尾**（まとめ直前が望ましい）。
- **執筆注記（※時点・Early Access 等）**はページ下部（脚注位置）。本文段落末に長い ※ を直書きしない。
- **行動喚起のポイント**は `.callout-point`（緑点線・白地・指アイコン・キッカー「ポイント」）。通常の注意/用語 callout と混同しない。囲み内は字下げしない。
- 1ページに詰め込みすぎない。溢れるならページを分割する（同じ page 型を複数枚）。
- `no-print` のツールバーは残してよい（画面操作用。印刷では消える）。**更新**（スクロール位置保持の再読込）と **印刷 / PDF** を維持する。

## 図・対比図

- 置き場: 作業コピー配下の `images/`（例: `book/images/`）。SVG（編集）＋ PNG（埋め込み、2x 以上）
- キャプション: `図: …`。図内タイトルと HTML キャプションの役割が被らないようにする
- 対比は **1行1軸**。ラベル重複を避け、中央スパイン化してよい
- 色: グレー基調可。見やすさのため役割色（既存側／主役側）を使ってよい。細いゼブラだけに頼らない
- 技術図の生成は fireworks-tech-graph 等を使ってよい

### 図の作成後チェック（必須・ユーザー報告前）

書き出し後に **PNG を目視**し、次を確認してから渡す。不備は直して SVG/PNG を両方更新する。

1. 文字同士の重なりがない  
2. 矢印・枠線が文字を貫いていない  
3. テキスト・図形が枠外にはみ出していない  
4. ノード／ラベル間の余白が足りている  
5. 文字と背景のコントラストが足りている  
6. 誤字・途中切れ・ラベル重複がない  
7. 座標計算だけで完了としない（必ずラスタを見る）

## 画面キャプチャ（UI スクショ）

製品画面を差し込むときは **`references/screenshots.md`** に従う。要点だけここにも書く。

- **Light モード**で撮る（ダーク禁止。ユーザーがダーク指定したときだけ例外）  
- **フォーカス切り出し**（フォームはカード周り、シェルはナビ＋主領域）。フル画面縮小で文字を潰さない  
- PNG **2x 以上**。差し込み前に目視（端切れ・暗いまま・不可読を落とす）  
- 本文の手順と UI 遷移を一致させる。変わったら図と本文を同じターンで直す  

## ことば（非エンジニア向け書籍のとき）

- 抽象語（「仕事場」など）より **場所・アプリ・道具** など具体語
- 用語はたとえ → カタカナ／英語の順
- はじめにの体験談と、章の用語・手順説明の役割を分ける
- **初めて触る読者**を本線にする。初回フローは実 UI の順（登録 → セットアップ → ホーム等）。深い設定は実践直前に回してよい

## デザインメモ（参照）

- 地色 `#FFFEFA` / 墨 `#3A3630` / 補足 `#8A8578` / 黄 `#F5E66A` / 囲み `#E8EEF6`
- 左右余白 19mm
- 印刷でも線が消えにくいよう border 中心

## 応答スタイル

- 日本語で対話する（ユーザーが他言語なら合わせる）。
- **作業前にタスク表を確認し、完了後に更新する**（「タスク表」節）。
- **章題が未確定なら、骨格 HTML や長文本文を先に出さない。** 先に章題リストで合意を取る。
- 章題フェーズでは、案を見せて「この並びで一気に骨格を作ってよいか」を明示的に確認する。
- 一括骨格の前後で、作ったページ一覧を短く要約する。
- 肉付けフェーズでは「今から第○章を詰めます」と宣言してから編集する。
- 先行作業を頼まれたら、指摘してから止めるか、明示許可後のみ進める。

## やらないこと

- 章題の合意前に、本編の長文や全ページの完成原稿を一括生成すること
- タスク表を読まずに肉付けや仕上げを進めること
- 章題変更後にタスク表・目次・章扉を食い違ったまま残すこと
- 本文段落の1文字字下げ（`text-indent: 1em`）を外す・付け忘れること
- 同一ページに `h3.sec-title` を2つ以上載せること
- 章末まとめを「この章でできたこと」にすること
- 章の途中に大きな用語表だけを挟んで説明の流れを切ること
- 図を書き出したあと、文字重なり等の目視チェックをせずに渡すこと
- 画面キャプチャをダークのまま載せる／余白だらけのフル画面をそのまま縮小して載せる（明示指定がない限り）
- テンプレート外の独自 UI フレームワークや別 PDF エンジンへの勝手な移行
- 著作権のある長文の無断転載
- スキルの `assets/` を「完成した1冊」として直接編集して終わらせること（作業コピーを使う）
